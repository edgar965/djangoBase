Das Konzept in drei Sätzen

  1. Seiten (HTML) kommen nie aus dem Zwischenspeicher. Wer nach einem Deploy die Seite von gestern sieht, sucht den Fehler im Code und findet ihn nicht.
  2. Statik (JS, CSS) kommt aus dem Zwischenspeicher — und zwar ein Jahr lang, ohne Rückfrage. Dass eine geänderte Datei trotzdem ankommt, besorgt die Fassung in der Adresse: neue Fassung, neue Adresse, neuer Eintrag.
  3. ES-Module bekommen die Fassung im Pfad (/statik/v-<fassung>/…), nicht in der Abfrage: Nur ein Pfad vererbt sich auf relative Importe. Deshalb {% templatetag openblock %} fassungspfad 'viewer/index.js' {% templatetag closeblock %} statt {% templatetag openblock %} static … {% templatetag closeblock %}?t=….

Nie „Strg+Shift+R" als Lösung vorschlagen: Damit ist der Fehler beim Entwickler weg und beim Benutzer noch da. Der Fix muss ankommen.

Was schiefging, bevor es so war

Der Fix kommt nicht an (drei Projekte, wiederholt, Stunden je Fall). Eine Datei ohne Fassung liefert der Browser aus seinem Zwischenspeicher. Die Seite lädt, sie führt nur eine alte Fassung aus — kein Fehler, nirgends. Ein „Konto löschen"-Eintrag galt als fehlend (assistant, 30.05.2026); im DOM war er da, der Browser hatte die alte Datei.
Die weiße Seite (WalkHop, 15.06.2026; 3DTools, 05.09.2026, zweimal an einem Tag). Ein versioniert geladenes Modul zieht seine relativen Importe ohne Abfrage nach; die kommen aus dem alten Zwischenspeicher. Bekommt das Modul einen neuen Export, bricht der Import: SyntaxError: The requested module './skinning.js' does not provide an export named 'skelettNachfuehren'. HTTP 200, leere Seite. Im Serverlog fehlt die Datei einfach — sie wurde gar nicht angefragt. Nachgestellt mit einem Playwright-Lauf, der genau ein Modul aus der alten Fassung ausliefert: das Modell weg.
Zehn Prozent des Dateialters. Ohne Cache-Control schätzt der Browser die Frische selbst: 10 % der Zeit seit Last-Modified. Eine drei Wochen alte Datei gilt zwei Tage als frisch. Der Entwicklungsserver beantwortet Statik vor der Middleware-Kette, deshalb sah die CacheHeaderMiddleware sie nie — die ASGI-Hülle StatikKopfzeilen setzt no-cache („vor jeder Benutzung nachfragen", ein 304 ohne Rumpf, nicht „nicht speichern"). Dieselbe Falle traf am 06.09.2026 große Binärdateien (GLB-Figuren mit nur Last-Modified): eine neu gebaute Datei gleichen Namens kann der Browser für 10 % ihres Alters behalten.
Ein Modul, zwei Adressen. modul.js?v=123 hier, modul.js im Import dort — für den Browser zwei Module mit getrenntem Zustand. Am 21.08.2026 zeichnete die Testaufzeichnung jeden Klick doppelt auf: zwei Aufzeichner, zwei Puffer, identische Zeitstempel.
Die pauschale NoCache-Middleware. no-store auf alles (ShortLongX, 3DTools bis 28.08.2026, Kommentar: „during development") — jede Seite lud sämtliche Module neu, und jede ?v=-Kennung war wirkungslos, weil ohnehin nie gecacht wurde.
Der Zeitstempel an der Statik. ?t={% templatetag openblock %} now "U" {% templatetag closeblock %} an Stil- und Skriptdateien ändert sich jede Sekunde: die Datei liegt nie im Zwischenspeicher, jede Seite lädt alles neu. Für Adressen von Daten (bvhUrl, Job-Ergebnisse) ist der Zeitstempel richtig — für Statik ist er die Abschaltung des Zwischenspeichers durch die Hintertür.
Die Kennung, die sich nie änderte. Statik.kennung() wurde einmal je Prozess gerechnet; der Entwicklungsserver startet bei .py-Änderungen neu, nicht bei .js. Ein neuer Listener kam nie an (18.08.2026). Seither wird die Kennung im Entwicklungsbetrieb je Aufruf frisch aus dem Dateibaum gelesen; der Fassungspfad hält seine Zahl höchstens zwei Sekunden.
Der falsche Hilfe-Präfix. Nicht Cache, aber dieselbe Sorte still: /help/ statt /hilfe/ ließ die Testaufzeichnung bei jedem Seitenaufruf dreimal in eine 404 laufen — ohne Fehlerseite, ohne Logeintrag. Gefunden hat es eine Seitenprobe, nicht das Fehlerlog.

So wird es in einem neuen Projekt eingerichtet

1. Middleware — nichts zu tun

CacheHeaderMiddleware trägt sich beim Start selbst in MIDDLEWARE ein (djangobase.apps). HTML bekommt no-store, Statik mit ?v= ein Jahr immutable, Statik ohne Kennung no-cache. Eine eigene NoCacheMiddleware gehört gestrichen.

2. Fassungspfad einhängen (urls.py)

from django.urls import include, path

urlpatterns = [
    path('', include('djangobase.fassungsstatik')),   # /statik/v-<fassung>/…
    …
]

3. Statik-Kopfzeilen um die ASGI-Anwendung (asgi.py)

from django.contrib.staticfiles.handlers import ASGIStaticFilesHandler
from django.core.asgi import get_asgi_application
from djangobase.statik_kopfzeilen import StatikKopfzeilen

application = StatikKopfzeilen(ASGIStaticFilesHandler(get_asgi_application()))

4. In den Vorlagen

{% templatetag openblock %} load static fassung {% templatetag closeblock %}

<!-- ES-Modul: Fassung im Pfad, die Importe erben sie -->
<script type="module" src="{% templatetag openblock %} fassungspfad 'viewer/scene/index.js' {% templatetag closeblock %}"></script>
const { start } = await import('{% templatetag openblock %} fassungspfad "js/spieler.js" {% templatetag closeblock %}');

<!-- Stil und klassisches Skript: ebenfalls Fassungspfad (oder ?v= mit einer Kennung, die sich mit der Datei ändert) -->
<link rel="stylesheet" href="{% templatetag openblock %} fassungspfad 'css/seite.css' {% templatetag closeblock %}">
<script src="{% templatetag openblock %} fassungspfad 'js/seite.js' {% templatetag closeblock %}"></script>

<!-- Daten: hier ist der Zeitstempel richtig -->
bvhUrl: '{% templatetag openblock %} url "serve_bvh" job.id {% templatetag closeblock %}?t={% templatetag openblock %} now "U" {% templatetag closeblock %}'

5. In JavaScript

import { Serverabruf } from '../gemeinsam/serverabruf.js';   // keine Abfrage, kein ?v=
const modul = await import('./teil.js');                       // erbt /statik/v-…/

6. Für Dateien, die der Server rechnet (JSON, GLB, Bilder aus Jobs)

Keine Fassung in der Adresse, also Cache-Control: no-cache plus Last-Modified oder ETag: Der Browser fragt nach, bekommt ein 304, solange die Datei stimmt, und sonst die neue. Ohne die Kopfzeile schätzt er — siehe „Zehn Prozent des Dateialters".

7. Prüfen

Hilfe → Tests: djangobase.tests.konform (darin test_cache, test_statik, test_cachekonzept). Hilfe → Skills: Werkzeuge cachebusting, cachekonzept, esmodulimporte. Und im Browser, nach jeder Änderung an einem Modul: die Seite laden und im Serverlog nachsehen, dass das geänderte Modul unter der neuen Fassung angefragt wurde — eine Datei, die gar nicht angefragt wird, kommt aus dem Zwischenspeicher.
